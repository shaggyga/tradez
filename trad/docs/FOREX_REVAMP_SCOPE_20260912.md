The user clarified that the existing demo accounts are spare environments for practice under live market conditions, with ample capacity already available. An inventory or reconciliation of every historical account alias is not a prerequisite for the research revamp. When a particular demo environment is used, bind its actual endpoint and experiment identity, preserve any original trial records, and prevent competing workers from submitting the same intent. These are local setup details for the chosen environment, not a separate account-capacity workstream.

**The original request to audit every model remains unfinished.** The previous work catalogued the older library and independently examined selected families, artifacts and results. It did not independently inspect and validate every distinct model and material variant across the entire project history. The 140-family catalogue is an inventory boundary for one older library, not the complete later model space. Its 29,366 run records, 10,072 variants, 13,273 applications, 1,060 datasets and 224 serialized-model references are different units; none should be presented as that many independent validated models.

The existing audit records grade 14 designated reference recipes reconstructable but not revalidated, one partial and 125 unresolved. They report 127 missing direct family-to-module associations. These are concrete audit/recreation gaps, not proof of absent implementations or bad performance. Later HGB, ARIMA, unified, MA, ridge, news, event and adapter work must be reconciled with the older catalogue rather than omitted or counted twice.

**First revamp work package: complete the model audit and archive map together.**

1. Inventory the union of canonical C project sources, D recoveries, AppData artifacts, vault/cold-library records and later study directories. Match both directions: catalogue entries to actual code/artifacts/results, and discovered code/artifacts/results back to an inventory entry. Structurally reconcile all retained run records, including the 29,366 older entries, without automatically refitting them. Record orphaned and missing references. Normalize duplicates without dropping materially different inputs, targets, training periods or cost rules.
2. Give every distinct model/material variant an evidence record: task/role; source and saved-artifact identities; exact ordered features and preprocessing; actual fitted fields; dataset locations, dates, sampling and row caps; prediction reference/target clocks; split/selection history; costs; original metrics and denominators; reconstruction recipe; operational integration; unresolved gaps.
3. Review every model's available performance evidence in its own context. Separate move detection, direction, signed magnitude, volatility/risk, event response and management decisions. A discovery score, smoke run, field catalogue, saved checkpoint or successful inference is not interchangeable with a validated strategy.
4. Assign an explicit disposition with supporting records: verified reusable component, retained negative/invalidated result, duplicate, implemented but unevaluated, or unresolved with the exact missing evidence. The audit should name useful roles even when no model qualifies as a whole trading policy.
5. Recompute or rerun only when needed to resolve a material evidence gap, missing verification or a stated changed hypothesis. This does not authorize silently skipping model records; it avoids automatically refitting all 29,366 historical entries. Preserve original failure records and previously inspected test periods.
6. Publish coverage counts with denominators and a gap list. “All inventoried models reviewed” and “all models independently reproduced/revalidated” must remain separate completion claims. Do not call the audit complete while undisposed entries remain; do not turn a clearly documented irrecoverable artifact into a fabricated reconstruction.
