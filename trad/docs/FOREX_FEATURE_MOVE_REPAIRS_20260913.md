## Implemented

**Complete versioned observation history.** The snapshot producer now retains primary scalars as well as per-timeframe scalars, explicit missing/nonfinite/default states, quote exclusions and original source metadata. Model-output scalars and nested forecast lineage are distinguished from technical indicators. Repeated primary/timeframe/unified representations share canonical identities when their definitions, values and clocks agree; disagreements remain explicit conflicts. The legacy Parquet training rows retain their prior layout.

**Accurate component clocks.** Observation, completed-bar and quote-source times are separate. Embedded M5 features use their own M5 origins even when contained in another timeframe's row. Order/position-book values use their own source clocks. Unknown clocks do not inherit a newly refreshed quote or generation time. Source definitions include the producer and observation implementation hashes, so changed definitions form a new comparison cohort.

**Immutable archives without prediction eligibility.** The existing snapshot producer writes the new observation archive before publishing its latest snapshot. This occurs independently of the downstream model worker's forecast/refusal outcome. Empty and excluded-pair observations are retained. A write failure remains an error, and cannot claim a completed latest publication. Deduplication checks source/snapshot identity and payload content; conflicting reuse is refused. Full normalized source envelopes are gzip-compressed under `data/oanda_training_manager/feature_observations_v1`. Nothing imports older records as newly observed evidence or rewrites the legacy archive. Helper calls with temporary output roots stay within those roots.

**Feature changes joined to pair moves.** The new read-only mapper compares before/after values for 5/15/60-minute windows using observations available at the requested endpoints. It shows requested and actual elapsed time, pair percentage/basis-point movement, source IDs, missing reasons and historical comparison counts. Feature changes are ranked by their absolute-change percentile against preceding comparable windows when enough varying history exists. This percentile is descriptive, not a probability of a correct forecast. Constant or insufficient history has no invented ranking score. Quiet/no-price-move and unchanged cases stay in the observations and denominators. Related pairs retain base/quote orientation and shared-currency labels rather than becoming independent confirmations.

**Meaningful feature units.** RSI changes are points, signed momentum remains in its original units, categorical features show transitions, and near-zero signed values do not produce misleading percentage spikes. Source/model/metadata distinctions remain visible. A pair filter runs before the display limit, so selecting a pair outside the global top rows still returns its own comparisons.

**Existing-dashboard integration.** An expandable feature-change panel and separate `/api/feature-moves` endpoint reuse the existing dashboard. They do not require a selected model forecast or consult trade eligibility. The reader opens only the new versioned archive with bounded directory, file, expansion and value limits; sampling/read failures are visible. Retained source hashes and reconstructed frames are checked before use. The original dashboard code and HTML outside the two marked additions remain unchanged; a presentation-only hash expectation has an explicit successor and a preserved predecessor receipt.

## Repaired legacy elapsed-window diagnostics

The legacy M1 technical helper now uses sorted, unique, completed bars and exact elapsed endpoint lookup instead of assuming a row count equals minutes. Missing endpoints, incomplete indicator histories, duplicate timestamps and stale observations are explicit. Its new calculation version distinguishes these results from retained older reports.

The old high-low statistic is retained under an accurate name. `atr14_pips` in the new calculation is the arithmetic mean of 14 true ranges using actual preceding closes and 15 consecutive bars. Missing closes/extrema do not receive invented open-price substitutes; preceding closes must also agree with their own high/low bounds. The loader's strict close/extrema mode is opt-in for this diagnostic; its original default API remains compatible. Older immutable reports and pinned scientific source generations remain unchanged.

The default mover source contains sampled quote-minute buckets. It now preserves their first/last sample clocks and distinguishes their requested bucket span from their actual price-observation span. A requested 300-second window can contain recorded endpoint prices 340 seconds apart. These samples are labeled separately from completed broker M1 candle inputs. Missing, reversed, out-of-bucket or inconsistent sample metadata cannot produce an available window. Contradictory bid/ask midpoints cannot reach charts or directional calculations. Source sample times remain metadata rather than authenticated arrival evidence: the older ticker does not identify every quote-time versus generation-time fallback.
