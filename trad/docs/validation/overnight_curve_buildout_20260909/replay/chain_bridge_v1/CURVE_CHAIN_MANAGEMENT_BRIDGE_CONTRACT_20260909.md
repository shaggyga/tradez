# Original-chain management bridge

`oanda_curve_chain_management_bridge_v1.py` implements the pure preparation and original-chain adapter needed by the separate entry/continuation selector. It is unregistered and inactive. It does not launch a shared-grid study, create a forecast, manage a position, settle a trade or measure performance.

The public call is `select_from_curve_chains(chains, quotes, state, *, decision_epoch, management_target_epoch, usd_config, trusted_context, observation_context, terminal=False, hold_only=False)`. `validate_bridge` rebuilds the same result from the same complete inputs and rejects a changed output even if its public hash was recomputed.

Each of at most 68 chains contains the complete original `curve`, `publication`, `consumption` and intended `management_target_epoch`. All intended management targets must equal the common supplied target. A valid curve may retain all of its other native nodes; the original adapter selects only an existing native node at the requested target. Missing nodes remain explicit refusals. Duplicate instruments and mismatched target contexts are rejected. Total original-chain JSON is bounded to 8 MiB and each original contract retains its own structure and byte bounds.

The trusted context fixes the supplied registry hash, original USD config hash, bridge dependency declarations and per-instrument forecast cohort, model artifact hash, feature version, native-head model IDs, original source bindings, curve policy, price convention, reference-price kind, bar duration and target-selection policy. It must come from an independently verified registry/source reader. The pure bridge neither reads registry bytes nor verifies files on disk; equality to supplied trust declarations is not independent source authentication.

The observation context supplies original read start/completion times and full object hashes for each curve/publication/consumption, the state and quote inventories, and the registry hash. It also supplies the state creation/known clock. Reads must finish by the decision cutoff, original availability must not follow each object's own read completion, and a position must already exist by the supplied state-known time. These are checks of caller-attested observations. The bridge does not manufacture read receipts, authenticate account state, or claim it completed its own computation at the earlier information cutoff.

The original curve contract first rebuilds and validates the complete issuance/publication/consumption chain. The bridge then checks the trusted identity and calls unchanged `admit_candidate_for_target`. This is contract and receipt reconstruction, not recomputation of a model's fitted coefficients or authentication of forecast authorship. Original raw input/model-inference verification remains the caller's responsibility when required by a prospective study.

An available original candidate is copied into a separately named `chain_bridge_decimal_clock_compatibility_v1_20260909` record. Its original candidate, schema and seal remain embedded unchanged. The native `remaining_sec` must exactly equal the original Python-float subtraction; even a one-ULP change is rejected. The compatibility record alone represents the difference as `Decimal(str(target)) - Decimal(str(decision))`. No timestamp, target, price, node, model, interval or original probability changes. It is not resealed under the original candidate schema.

Both USD preparation channels run under the existing 50-digit mechanics context. Every available prepared estimate enters the continuation inventory, including opposite-signed and zero estimates. Only semantic entry admissions enter the entry inventory, using that exact same prepared row. Thus an old short terminal crossed by a falling market cannot become new long entry evidence, while its signed value for either existing position side remains available. Cost hurdles and the original USD hold/exit/rotate economics are unchanged. Missing quotes, stale/nontradeable quotes, missing chains, elapsed or unavailable native nodes and failed USD preparation retain explicit reasons. No missing forecast becomes zero.

The existing exact-versus-nominal management policy remains explicit. A retained first-complete-bar target window of 0–7 seconds is preserved as a nominal management approximation when specifically allowed, and refused under exact-only policy. This bridge does not solve the future shared-grid study's exact-target predictor/registration requirements. Original full-horizon probabilities and intervals never become calibrated conditional remaining-risk distributions.

Validation: 37 focused full-chain synthetic cases passed. A subsequent single integration run covering the bridge, separate channels, direction admission, original adapter, original curve contract and original USD mechanics passed 315 cases in 10.73 seconds with all 13 source/test hashes unchanged. These overlapping counts must not be added. Independent source review found no blocker and did not rerun tests. The initial two failures were incorrect fixture expectations: a three-pip prediction did not clear the unchanged spread/slippage hurdle, and numeric zero was rendered `0.0000`. Initial bytes and failed XML are retained; the implementation was not changed to conceal those failures.

No broker requests, actual account state, raw news, live quote captures, runtime processes, model fitting, new registry, counterfactual PnL or predictive-improvement claim is part of this implementation.
