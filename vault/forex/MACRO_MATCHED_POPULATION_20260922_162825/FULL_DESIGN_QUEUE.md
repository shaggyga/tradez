## Acceptance rule for every pending change

Each change records: design section and R/WP IDs; predecessor/existing path; demonstrated gap; exact input/output contract; affected descendants; required acceptance-test IDs; actual result and tolerance; evidence status; resource limits; recovery/checkpoint instructions; and next unblocked step. A fix to infrastructure does not count as new market evidence. A new model must name the closest previous experiment, material difference, matched baseline, stopping rule and independent confirmation route.

No pending change is complete solely because a file exists, tests of a different component pass, an import works, or a report says “retired.” Preserve useful negative findings without promoting compromised diagnostics into valid negatives or retiring entire model families. The earlier Stage C “exactly one new candidate next” directive is superseded by B/C, not executed alongside them.
