Audit and search grace/minimum holds, soft age penalties, challenger advantage, persistence, cooldowns, stale/max duration, surface deterioration, launch failure, uncertainty, profit protection, trailing exits, and event-sensitive replacement. Use conditional/horizon-normalized forms as well as fixed settings. Optimize defensible ranges within historical selection, not a giant blind Cartesian grid.

Compare no optional rotation, naive top-rank replacement, recovered policies, cost-aware hysteresis, and learned continuation variants. Hold risk/sizing fixed initially. Produce a turnover-versus-performance comparison rather than assume faster switching is better.

### 21. Execution, accounting, and constraints

Separate decision, validation, submission, order activation, fill, cancellation, and settlement. Newly submitted orders cannot fill retrospectively in the bar used to make the decision. Resting orders follow a different observation history.

Use executable bid/ask data where present. Model latency, slippage, spread, commissions if applicable, financing/rollover, weekends, market closures, rejected/partial/missed fills, order expiration, gaps, precision, minimum sizes, and instrument-specific margin. Verify actual provider semantics and historical assumptions from official documentation; do not silently apply current specifications throughout history.

Keep source movement metrics in pips/returns and portfolio accounting in the account currency using contemporaneous conversion. Never rank unequal exposures solely by nominal pip counts. External currency exposure, maximum loss, margin, and drawdown limits cannot be optimized away.

With ambiguous target/stop ordering inside a candle, use finer retained data first. Otherwise preserve ambiguity, use a prespecified conservative primary execution convention, and report alternative bounds. Do not train labels as if the convention were an observed path. Do not selectively omit inconvenient ambiguous cases.

Gap-crossed stops need plausible gap fills, not guaranteed stop prices. Limit touches do not automatically guarantee fills. For pending/OCO policies, model cancellation latency and potential double fills; do not grant perfect coordination from coarse bars.

Replay decisions under stressed costs when costs affect behavior, rather than merely subtract larger fees from an unchanged trade list. Reconcile cash, realized/unrealized P&L, financing, conversions, margin, and equity continuously. Compare an optimized engine with a simple reference engine on decisions and accounting, not just final P&L.

### 22. GPT advisor curve and quantitative controls

Implement independent experimental arms, not only one GPT account. Use configurable axes for actual model ID/checkpoint, supported reasoning effort, information packet, role, cadence, and approved inference budget. Verify current API names/capabilities/pricing from official documentation at execution time; do not assume informal model nicknames from prior chats are valid API IDs.

Core controls:

    Q0: quantitative decisions with non-GPT numerical/deterministic inputs.
    Q1: quantitative decisions with explicitly shared GPT-derived NLP features,
        if that extraction is an approved experiment.
    A*: GPT decisions from the point-in-time information system.
    AF*: GPT decisions with quantitative horizon forecasts additionally supplied.
    H*: a precisely defined hybrid review/veto/reranking role.

Across advisor arms, test cheaper/faster versus stronger models, and reasoning levels within the same model. Treat model, reasoning, information, and cadence as separate axes. Add specialists or a consensus arm only under a bounded design; avoid a full expensive Cartesian campaign.

An information-led GPT need not follow quantitative ranks or await completion of the entire model search. It can interpret valid technical, macro, currency, and portfolio information directly. Forecast-assisted versus information-only comparisons measure whether numerical forecasts help or anchor its decisions.

Code computes economics and enforces hard limits. GPT recommends structured actions, evidence references, intended horizon, and invalidation conditions. Do not request or store hidden chain-of-thought. A concise stated rationale is not causal proof of why the model acted. Self-reported confidence is not an empirically calibrated probability.

All arms get the same eligible universe and documented common risk/execution framework. Accounts may disagree. A consensus arm is a separate policy, not a requirement that every account approve every trade.

### 23. Small matched-decision advisor tournament first

Before paying for long advisor replays, implement a 20–50-case pilot with identical decision states and information packets. Select by predefined contemporaneous conditions: near-ties, ordinary activity, range states, event windows, temporarily losing incumbents, profitable weakening incumbents, strong challengers, and no-trade situations. Avoid selecting only cases whose subsequent outcomes look dramatic. Keep handpicked edge cases separate from a representative evaluation sample.

Give each candidate matched timestamps, information, holdings, capital, allowed actions, and opportunity coverage. Use compact full-universe summaries plus consistently selected detail; record truncation and shortlist rules. Do not drop pairs simply because a prompt is large. Historical tools must query the same frozen snapshot; disable unrestricted current web/news access during historical decisions.

Use an illustrative 3–5 repeats per model/configuration where budget permits. Repeats measure response variation, not additional independent market observations. Prevent retry cherry-picking; record errors and retries. Cache exact responses by request/version/repeat ID so resume does not silently repeat paid work.

Require validated action fields: action type, instrument, side, quantity/risk proposal, horizon, referenced evidence, thesis/invalidation, and uncertainty when applicable. Record latency, token/API expense, invalid actions, and fallback behavior. Provider outages do not disable deterministic risk monitoring.

Commit all responses before revealing outcomes. Evaluate agreement, within-model stability, after-cost outcomes under a fixed continuation contract, and feasible decision regret. The pilot detects behavior differences; it does not establish a robust trading edge or conclusively prove models equivalent.

Then run independent portfolio replays: every arm starts from matched conditions but owns its evolving positions and memory. Use common information generation where policy-independent and causal branch-specific histories where not.

### 24. Prospective shadow and demo campaign

Build a multi-arm campaign registry with arm ID, model/policy versions, account alias, capital/risk settings, launch time, cadence, budgets, and evidence status. Prepare one-to-one account/arm assignment checks and idempotent order IDs. Never send duplicate orders because a worker restarts.

Default to shadow. Enable demo submission only after explicit assignment/authorization and successful reconciliation tests. Do not reset or normalize real demo balances by changing accounts; report initial differences or use matched simulated equity alongside actual demo behavior.

Share a timestamped information snapshot service, not shared holdings or account-learning state. Track actual quote availability and request completion. Compare matched-information decision quality separately from real-latency operational performance.

Maintain hard stale-data, loss, exposure, and connectivity safeguards independent of GPT. Continue risk monitoring during failed/slow advisor calls; use a predetermined fallback. Changes to model, prompt, selection procedure, or account rules create a new version/cohort rather than rewriting the old track record.

Evaluate prospective model replacement as an adaptive policy with recorded change times. No outcome here automatically authorizes real-money deployment.

### 25. Calibration, ranking, uncertainty, and scorecards

Keep forecasting, calibration, opportunity ranking, position management, execution, and portfolio scorecards separate. A feature/model need not be a profitable standalone strategy to contribute; its incremental value still requires held-forward evidence.

Use target-appropriate metrics: signed/absolute error versus no-change and simple baselines; Brier/log loss for probabilities; quantile/CRPS or suitable distribution scores; interval coverage; first-passage calibration; timing errors with censoring; and opportunity ranking at matched horizons/exposures.

For ranking, report top-1/top-3/top-5 realized outcomes, rank correlation, cost clearance, and availability/abstention. A rank score is not automatically expected profit. A correctly ranked set of losing candidates still favors cash.

Measure model uncertainty, disagreement, horizon disagreement, feature-state novelty, calibration drift, and source-quality uncertainty separately. Reliability/meta-models must learn from honest matured predictions. Agreement counts across correlated models are not probabilities or independent evidence. Any conformal/uncertainty technique must state its assumptions and empirical conditional limitations.

For portfolios report account-currency outcomes, return, drawdown, downside/tail behavior, profit factor where defined, turnover, hold duration, costs, exposure, concentration, and decision validity. Report gross, market-cost-net, and API-cost-net variants; do not silently treat API expenditure as zero or scale dollars to incomparable exposure.

### 26. Hindsight diagnostics, opportunity availability, and regret

Measure the hypothesis that useful intraday movement often exists somewhere in the 68-pair universe. Distinguish any large ex-post excursion, an economically feasible trade under defined rules, and a prospectively forecastable opportunity. Those are different claims.

Construct hindsight diagnostic benchmarks under explicit capital, concurrency, delay, cost, fill, and risk constraints. If the hindsight optimizer is approximate, label it a feasible hindsight benchmark—not a proven global ceiling. Keep impossible perfect-path selection separate from feasible-policy comparisons. Never promote a strategy by proximity to an unconstrained oracle.

Compare with no-trade, fixed-hold, simple momentum/reversion, recovered quantitative policies, and a matched random/rank control where appropriate. Deduplicate shared currency/event opportunities.

Trace premature exits, overdue holds, late entries, ranking mistakes, unnecessary replacements, duplicate exposure, sizing, and cost drag. For HOLD/EXIT/SWITCH counterfactuals specify continuation policies, common valuation horizons, and fill assumptions. Do not sum overlapping regrets as independent recoverable dollars.

A profitable original trade does not prove holding was the best action; a losing exit does not prove it was wrong. These diagnostics support investigation and training on earlier data, not hindsight access during evaluation.

### 27. Statistical safeguards and negative controls

Keep one global chronology. Account for overlap across horizons, repeated forecasts, pairs sharing currencies, event episodes, and repeated advisor samples. Do not report millions of rows as millions of independent tests.

Use suitable chronological/block/event-level uncertainty methods, paired comparisons where states match, and hierarchical multiple-testing control where appropriate. Record all attempted configurations, thresholds, feature searches, and procedure revisions—including failures and stopped trials. Protect confirmation data from repeated tuning.

Minimum support should reflect distinct episodes, horizon, regime coverage, and economically material effects. Insufficient data is inconclusive, not a proven failure. Calibration or precision should not be reported without denominators and coverage. Avoid fixed sample thresholds detached from dependence and power.

Run meaningful negative controls: irrelevant inputs, appropriately block-shifted outcomes/features, scrambled macro/currency assignments under a defined null, and no-information predictors. Explain what dependence each control preserves or destroys. Investigate systematic false skill rather than declaring failure from one lucky null run.

Audit the selection process itself. Fast screens, hypothesis seeding from the Vault, and manual choices consume research degrees of freedom. Do not sell a discovery-selected surface as untouched evidence.

### 28. Compute strategy, caching, and resumability

Benchmark actual I/O, feature construction, labels, fits, inference, and replay before predicting total runtime. Establish configurable CPU/GPU/RAM/disk and wall-time budgets. Avoid nested all-core jobs, unbounded model downloads, and unlimited API calls.

Cache by dependency fingerprint: raw data version -> deterministic features/targets -> prefix-specific learned transforms -> model -> historical forecasts -> policy replay. Rebuild only affected descendants. Validate any reduced precision near trading thresholds. Keep bulk working data outside small cloud-sync checkpoints when appropriate without deleting authoritative source histories.

Keep all 68 pairs represented in initial coverage and cheap baselines. Use common chronological blocks, representative regimes, and all relevant event classes. Reduced forecast-origin density may be a screen while M1 paths remain available for execution; finalists need intended-cadence evaluation.

Use broad bounded exploration, adaptive sampling or successive halving, refinement, and full replication. Do not compare a macro model's quiet period with a technical model's event-rich period. Retain minimum exploration for rare events, specialist pairs, and interaction-only effects. Fully evaluate a sample of pruned candidates to audit screen reliability.

Every expensive task must checkpoint with exact config, seeds, data dependencies, completion state, and resource usage. Atomic writes, locks, resumable partitions, worker heartbeats, and a single report writer must prevent corruption and duplicated work. Interruption/resume should reproduce uninterrupted results, subject to documented nondeterministic backend limits.

Produce a straightforward Windows launcher and resumable CLI using existing entry points or a thin orchestrator. Avoid a giant duplicate monolithic backtester. Stop at budgets and leave a clear continuation command; do not claim jobs run in the background unless a process was actually launched and verified.

### 29. Information-value experiments and optional paid signals

Evaluate technical-only, cross-currency-only, macro-only where sensible, and combined families. Add event existence, numeric expectations, NLP state, semantic change, and market reaction separately. Test standalone, incremental, and decision value rather than a single leaderboard.

Paid signals are optional external data candidates, not required infrastructure. No purchases. A useful evaluated feed needs timestamped complete history, revisions/cancellations, entry/stop/target rules, expiry, and retention of losing signals. Backfilled winners or screenshots are not an auditable input stream.

Prioritize identifying unavailable information—such as genuine historical expectations, suitable positioning, or options-derived data—over paying for another opaque transformation of the same charts. This is a data-gap assessment, not a recommendation to subscribe. Evaluate approved feeds against the system alone and the combined system after subscription/API costs.

Stage A: establish source authority, inspect active-process safety, index evidence, and recover relevant existing implementations. Produce the initial reuse map and exact blockers. Audit the core dependencies before changing them; continue deeper catalog reconciliation incrementally.
