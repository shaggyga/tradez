## Mandatory duplicate check before another experiment

1. **Locate the existing family, variant, application and run.** Search the 140-card catalogue and later 38-group audit; record predecessor report and artifact hashes. A renamed wrapper is not a new hypothesis.
2. **Compare actual inputs and targets.** Record ordered schema, transformations, fitted subset, currencies/pairs, reference convention, horizon and target tolerance. Distinguish implemented features from fields actually consumed by saved weights.
3. **Match evidence conditions.** Bind dataset bytes, original availability/ingestion clocks, gap policy, chronological splits, purge, selection history, costs and denominators. State whether the proposed test was already inspected.
4. **Check reconstruction first.** Bind code, dependencies, environment, artifact bytes and exact generation command. Missing aliases should be resolved against recovery copies; a recipe gap is not permission to silently substitute weights or data.
5. **Name the reason to run.** Permit a new run only for a stated changed hypothesis or missing verification: for example, repaired timing, different information, compatible fresh updates, or prospective confirmation. Preserve the original failed result and specify what this run can resolve.
6. **Record disposition afterward.** Append the new identity, result, caveat and reuse decision; never replace earlier evidence or add overlapping N. Separate source correctness, predictive performance, management economics and deployment status.

The immediate curve-management gap is fresh forecast updates with a reviewed reference and target contract. Risk attachment needs a compatible grid, but the existing draft allows valid curve updates when that attachment is unavailable. Conditional remaining-risk modelling is required only for a controller that uses it. Existing direction-admission and chain-bridge helpers remain separate from live management; old terminal rebasing and full-horizon risk quantiles cannot supply fresh conditional estimates.


## September 12 UTC — signed-cost and meter reuse follow-up

The older executable-opportunity rankers already used gradient boosting, absolute magnitude, conditional direction, Platt calibration and cost thresholds. Direct signed regressors also existed. The new comparison corrects the interpretation of the clearance-probability × median-magnitude proxy by estimating unconditional signed means, or positive/nonpositive conditional means with matching population weights, on the new shared technical/peer/news panel. It is not a new invention of boosting, calibration or magnitude modelling.

Eight retained bundles, four horizons, 24 learned policies and 39,893 reused-history assessment rows: calibration scores improved in eight of eight aggregates, but 17 policies were negative, four positive with limited/inconsistent support, and three inactive. Do not nominate the small positive cells as proven winners or repeat the same inspected dates as confirmation. Older V12 currency-meter history ends September 5; its implemented 66-field projection was not backfilled into this study. Current capture restarts retention under a separate source-bound cohort; continuous service remains uninstalled.
