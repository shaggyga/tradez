# Entry-eligible news and event-response features

The new pure diagnostic is implemented in `trad/oanda_entry_news_feature_join_v1.py`. It retains the existing eight news feature names and their relationship to the current model's 24 price fields and two interactions. It does not fit, publish a forecast, activate a worker or replace the frozen 34-input adapter. The final validation receipt binds the exact source, tests, review and evidence files.

The measured snapshot is **September 9, 2026, 05:46:18.812 UTC**, rather than a claim about all subsequent news. Its source cutoff was 05:45:38.969, generation 05:45:40.490, actual file-read completion 05:46:16.465 and replay/consumer observation 05:46:18.608 UTC. The 3,669,255-byte original snapshot and seven producer source hashes were retained; complete original-source replay passed. Later offline diagnostics preserve these original clocks and record their own later evaluation time.

The snapshot contained **22 guarded topics and 59 members**. Applying the new entry-feature policy to the same frozen bytes produced:

| Membership | Count | Interpretation |
| --- | ---: | --- |
| Recent context-only members | 4 | Classifier context available at the cutoff; not a forecast or vetted direction |
| Vetted forward topics | 0 | Original verification, corroboration and reaction-window rejections remain intact |
| Post-move discovery members | 11 | Descriptions of earlier market moves, kept outside entry features |
| Members outside the one-hour context window | 44 | Original event/known clocks were not renewed by reading them again |

Pair-relevant context support was **EUR/USD 4, GBP/USD 3 and USD/JPY 3**. All three had zero vetted-forward support. A complete observed empty population permits a zero count feature. An undefined balance or age remains `null`; missing or stale evidence makes every affected feature unavailable. The old model's numerical defaults are exposed separately as defaults, never described as measured neutral news. Broad-context features may include vetted members when they exist; `context_only` and an overlap count make that relationship explicit.

A separate indexed sample selected at most 128 mappings from the latest 32 observed committed news batches. **All 128** substantive payload identities, mapped hashes and independent mapping-visibility contracts verified. Nine had nonempty currency-score maps and 34 were flagged as prior-market-move reports. These are sampled historical mappings, not 128 independent current events or a complete history census. No new read time was substituted for their original mapping visibility.

The existing recovered-blurb response contracts still contain **1,042 v1 rows and 1,274 v2 rows**, with **zero non-null prequential predictions in either contract**. Their separate distinct underlying-event counts are 131 and 160; these counts cannot be added as a unique-event total. The existing algorithm requires at least three earlier matured analogs and a nonzero orientation; it describes itself as retrospective discovery. It was not activated or recalculated here.

The bounded factor/response sample contained 128 factors and 128 v2 responses. None could be admitted as causal memory from those sampled schemas: original independent source visibility, feature-availability and consumer-observation clocks were not retained there; response rows also lacked an exact outcome-known timestamp and a separate original first-seen field. Their reported known-time is preserved separately, rather than relabeled as first-seen. A target clock is insufficient. This is a limitation of these sampled records, not a claim that every other official-event dataset lacks clocks. The existing source-response history adapter already distinguishes `quote_time_utc` from `sampled_utc` and withholds direct responses without exact outcome-known evidence. Its retained August 17 report is historical and was not presented as current coverage.

The new join accepts caller-attested evidence only after checking cutoff clocks, the exact seven-source closure, topic/member guard replay, immutable identities and pair attribution. Exact duplicates collapse; conflicting member identities, overlapping directional support and conflicting topic IDs cannot add votes. Historical factor/memory records additionally carry their original factor type and source contract. Memory requires a source-first candidate universe, feature visibility before the response starts and both target maturity and actual result observation before the cutoff. It never learns an orientation or selects rows by profitable outcomes. Checksums protect integrity; a pure function cannot authenticate invented I/O receipts.

The next integration is to retain those missing observation fields and source-first membership prospectively, using the existing factor contract and market-episode ontology. Join them to the same price cutoff and evaluate a separately registered extension against price-only and the current joint model on matched future outcomes. The ontology already forbids profit-dependent cohort boundaries. This work supplies an eligibility boundary and measured missingness; it does not establish a useful learned news effect.

Validation: **121 passed: 56 new join tests and 65 existing guard tests**. Fixtures cover genuine measured zero versus missing/empty, late/future/expired clocks, unknown classifications, post-move explanations, duplicated publishers/members/topics, matured response availability and source-first membership. The initial draft's optional empty-clock parser issue and an external replay helper's Windows text-decoding issue are retained in development artifacts; both were corrected before acceptance. The final frozen-sample replay uses original UTF-8 bytes, with unchanged source observations and eligibility counts. No production data, registered model source, registry, runtime process or vault record changed.
