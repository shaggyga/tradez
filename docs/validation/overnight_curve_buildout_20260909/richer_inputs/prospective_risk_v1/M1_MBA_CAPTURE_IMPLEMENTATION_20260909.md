# M1/MBA capture and exact source mapping — September 9, 2026

The new unbound `oanda_m1_mba_research_capture_v1.py` supports one read-only practice-instrument candle GET per call, solely for EUR/USD, GBP/USD and USD/JPY. The fixed query is M1, MBA, count300, smooth=false. It has no account endpoint, order method, runner, file writer, retry or redirect; environment proxy settings are disabled. Credential parsing reuses the unchanged source-bound read-only helper and only selects the API token.

`capture_once(instrument, *, credential_path, metadata, clock=time.time)` returns exact response bytes and a sealed receipt. Required metadata contains instrument/base_currency/quote_currency/pip_size, with exact supported pip strings. Actual clocks are request_started_epoch, read_completed_epoch, first_observed_epoch equal to read completion, and capture_completed_epoch after validation. Request duration is explicit. HTTP Date is diagnostic, never an availability timestamp. The receipt binds this module and the credential parser, request/limits, raw byte hash/count, full-response disposition, complete/incomplete counts, original coverage and inert flags. Complete bounded error responses are retained with failed receipts; oversized/failed streams retain only bounded partial bytes with that limitation explicit. Exception/request strings containing credentials are not serialized.

`map_verified_capture(raw, receipt, metadata)` is pure after module loading. It replays exact retained raw bytes and original read clocks, with no new availability time. It rejects mismatched sources, request identities, receipt seals, malformed/duplicate JSON, wrong pair/granularity, non-minute timestamps, out-of-order or duplicated bars, incomplete-then-complete ordering, invalid M/B/A OHLC and prices, future completed closes, volume/type errors and changed coverage. Explicit complete booleans and positive exact decimal OHLC strings are required. Official M values remain official M; bid/ask are retained separately. No S5 aggregation, midpoint reconstruction, inferred spread, smoothing, fills or candle tradeability inference is performed.

The result includes `canonical_csv_bytes`, `complete_rows`, `incomplete_rows`, `coverage`, `source_attestation` and `mapping_sha256`. Each complete row retains bar_label_epoch, price_epoch=label+60, available_epoch=original read completion, time_text, volume and exact M/B/A o/h/l/c decimal lexemes. The canonical CSV contains complete rows only and roundtrips through unchanged `oanda_m1_path_risk_labels_v1.parse_csv`. Its SHA/bytes/row_count are in `canonical_csv`. `mapping_document(mapping)` verifies that byte binding and returns detached JSON-safe evidence; the mapping seal covers that document without the CSV byte object or seal field itself.

Source attestation uses raw_sha256, receipt_sha256, read_started_epoch/read_completed_epoch, complete_provider_response/source_query_complete and first/last_complete_bar_label_epoch. Coverage is only the entire returned complete-row domain. Gaps remain explicit; no domain is inferred before the first or after the last complete row. The consecutive suffix count helps explain the separate204-real-bar warmup requirement. The downstream publisher must choose only exact originally scheduled five-minute origins, establish its actual consumption/issue/publication clocks, preserve original reference OHLC and enforce positive real60-return volatility support. This module issues nothing and does not fill missed schedules.

60 focused tests passed in3.82 seconds with zero failures/errors/skips; all HTTP activity was mocked. The prior57-case XML is preserved before three added type-coercion fixtures. Tests cover fixed routing and transport, all three pairs, parser/lexeme compatibility, gap and incomplete retention, source/request/clock tampering, strict numeric types, low Decimal-context invariance, raw failed-response preservation, bounds and sanitized errors. No actual GET, broker action, model fit, runtime activation or frozen-source edit occurred in this implementation phase.

Known limits: accepted-response wall-clock checks and requests connect/read timeouts do not guarantee hard process cancellation during every DNS/stalled-stream condition. Module-load source fingerprints are not remote authentication; actual request collection separately verifies disk sources before/after the GET. Caller-retained receipt persistence remains the external trust anchor. The frozen retrospective label parser still labels historical ingestion/completeness as unproven; this new mapping supplies separate prospective raw-source evidence and does not claim its official-M convention equals unknown original training ingestion.
